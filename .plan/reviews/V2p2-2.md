## F1 — WITHDRAWN

`mentionsSnakeCaseKeys` now recurses under `CASING_SCAN_DEPTH = 4` with arrays transparent, and the depth-2 site the readers descend to is reached.

**The headroom is real, and I measured it rather than reading the constant.** I placed a snake_case key at each successive object level and asked the shipped detector:

```
object level      0     1     2     3     4     5     6
detected       true  true  true  true  true  false  false
```

The deepest **real** site — `records[] → record → artifacts[] → artifact` — sits at object level **2** and is detected. So the cap admits five object levels where three are in use: **two levels of genuine headroom**. The claim in the docstring is accurate.

**And the correction it made to its own first attempt was necessary, not cosmetic.** With arrays consuming a level, the real deepest site sits at exactly the budget — `records[]`, its element, `artifacts[]`, its element — so `4` would have been the minimum dressed as a margin, with the docstring asserting headroom the code did not have. That is the same defect class as a magic number that silently unguards a race: a constant whose stated slack is zero. The reasoning behind the fix is also the right one on the merits — *a list is not a level of naming; the keys live on the objects inside it* — so counting arrays would have made the budget a fact about container shape rather than about name depth. Injection **AE** (arrays consume a level again, cap reduced by one) confirms it: **+2 failures**.

**The injection evidence reproduces, and the pairing genuinely closes the trivial-satisfaction hole.** Deltas over my own baseline (768 tests, 2 known `registry.test.ts` failures):

| injection | result | delta |
|---|---|---|
| **AC** — the shipped F1 defect restored verbatim | 4 failed | **+2** |
| **AD** — cap cut to one object level | 4 failed | **+2** |
| **AE** — arrays consume a level, cap reduced by one | 4 failed | **+2** |
| **AF** — detector unconditionally `true` | 23 failed | **+21** |

AF is the half that matters and the slice's reasoning for it is exactly right: AC, AD and AE all assert the detector says `true` where it previously said `false`, and **every one of them is satisfied by a detector that simply answers `true`**. AF closes that — 21 tests fail if the detector fires on a correct payload, because a notice that always shows replaces every section's content with a complaint. So the suite brackets the detector from both sides: it must fire where it should and stay quiet where it should not. That is the same assert-presence-and-absence discipline this run keeps arriving at, applied without being asked.

**The test shape is right, and the whole-ladder pin is the better choice.** Pinning `[true, true, true]` rather than only the level that broke is correct for the stated reason — a fix that moved the blind spot from two to three would pass a test checking only two — and it is cheap. Pairing it with `readRecordsPayload(...).artifacts === []` in the same test is what makes it carry *why* the notice is load-bearing rather than just the detector's answer; a reader who later wonders whether this test is worth keeping finds the consequence sitting next to the assertion. The false-positive guards are the right two: a correct payload at the new depth, and `evidenceSpan: "as_written"` — a camelCase key whose *value* contains an underscore, which is the classic way a widened detector starts crying wolf.

**On screen it asserts all three things that can go wrong**, which is more than I asked for: the notice is visible, the swallowed value (`"a parcel"`) is absent, and the card itself is absent — so nobody can read "no artifacts yet" off a payload the console could not parse. The middle assertion is the one most tests would have omitted.

**It reproduced my probe before fixing.** It got the ladder and `readerProducedArtifacts: []` exactly, and independently re-enumerated the descents to the same conclusion — `unbound[]` (433), `messages[]` (489), `placement` (411) at depth 1, `readParkedPayload` at the root, `records[].artifacts[]` (376, 394) the only depth-2 site. Confirming a finding by measurement before acting on it is the right habit, and it is what makes the fix's scope trustworthy rather than merely plausible.
