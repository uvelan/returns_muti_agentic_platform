## The screen (`/config/policy`, section name "Policy")

Top to bottom, in this order, on the `TypedSectionScreen` chrome (Advanced/JSON toggle, DiffPreview, Validate, Publish, audited):

1. **Policy evaluation** — one large `Toggle` bound to `policy_evaluation.enabled`. When switched off the reason field (`disabled_reason`) is required and shown inline; when on, the reason must be absent (the model's rule). Under the toggle, one sentence in the platform's words for each state: on — "Every return is judged against the rules below before the case proceeds"; off — "No eligibility decision is recorded; cases proceed and carry the reason as `CONDITION_FACTS_NOT_EVALUATED`" (confirm the exact recorded rule name from `return_case_activities.py` and use that).
2. **Defaults for all products** (`standard_stock_return`) — return window: `NumberField` days (packaged default 30, min 0, unit "days") and `EnumSelect` basis (`ReturnWindowBasis`); decision when satisfied (`EnumSelect` of `EligibilityDecision`); what an unstated condition fact decides (`unstated_condition_facts`, `EnumSelect`, with the packaged file's own explanation of `REVIEW_REQUIRED` vs `NOT_EVALUATED` as the hint); conditions attached to approval (`conditions`, `TagListInput` limited to the model's enum). A "Reset to packaged default" link per field that sets the field to the packaged value (from item B below), shown only when the value differs.
3. **What the item must be** — the requirement checklist as `Toggle` rows in two groups: condition (`new`, `suitable_for_resale`, `original_packaging`, `packaging_undamaged`, `all_original_parts`) and prohibited states (`used`, `installed`, …), plus `seller_stocked` / `special_order` flags; each labelled in plain words.
4. **Outside the window** (`outside_standard_window.decision`, `EnumSelect`) and **restocking fee** (`applies_by_default` `Toggle`, `seller_can_waive` `Toggle`, `amount_source` `OrderedList` of the enum, `percentage`/`amount` shown read-only as "not published by Ferguson" since the model types them `None`; `seller_schedule` `KeyValueTable`).
5. **Exceptions** — stock classification: `unresolved_default` `EnumSelect`; `special_order_skus`, `special_order_sku_prefixes`, `special_order_product_ids` as `TagListInput`s; special/non-stock decisions (`special_or_nonstock`) and delivery claim / warranty blocks as `FieldGroup`s with their `EnumSelect`s and `TagListInput`s (the parts `ReturnPolicySection` renders today move here unchanged in behaviour).
6. **Precedence** — `OrderedList`; `FERGUSON_STANDARD_RETURN` pinned last with the reason from the packaged comment.
7. **Preview a decision** (right column or bottom panel, like the support-template preview): a small form — days since purchase (default 10), stock classification (standard / special order / unresolved), condition facts as tri-state (yes / no / not stated) for the checklist, reason — and a "Evaluate" button calling item A below with the **draft** in the editor; shows decision, applied rule ids, conditions, and the unanswered checks. This is what lets an operator see that "30 days, all products" does what they think before publishing.

## Backend items (read-only, no persistence)
A. `POST /api/config/policy/preview` body `{return_eligibility_policy, policy_evaluation, sample: {days_since_purchase, stock_classification, facts: {…}, reason}}` → runs `policy/evaluator.evaluate_return_eligibility` with a fabricated case built from `sample` (never a real case; no graph read) and returns `{decision, applied_rules, conditions, unanswered_checks, evaluation_enabled}`; when `policy_evaluation.enabled` is false returns the not-evaluated outcome the workflow would record. Validates the submitted blocks with the same models as `/validate`. Read roles.
B. `GET /api/config/packaged/{domain_key}` → the composed packaged document for the domain, redacted, read roles (used for "Reset to packaged default" and reusable by other screens). Both routes in the three OpenAPI copies; drift check PASS.
