## Scope

### Backend
1. **Normalization** — new `operations/return_support/ingress.py`: `NormalizedSupportEvent` (contracts.md §5). Structured mapper: `ReturnOutcomeRequest` → event (record groups; no LLM) — anchor `api/return_support.py:597 submit_return_outcome`, `_support_event_id`. NL endpoint `POST /api/v1/return-support/work-items/{id}/messages` (new `api/support_ingress.py`): `SupportInboundMessage{external_message_id, body_text, sender, channel_hint}`, `RETURNS_SUPPORT_ACT` + case access, size/rate limits from `support_ingress.limits`. Dedupe `(case_id, transport_id, external_message_id)` → internal `support_event_id`; persist raw + event + outbox row (topic `return-case.support-message.classify`) in one transaction via the `DurableSupportEventStore` extension (anchor `operations/support_events.py`).
2. **Parked lifecycle** — `nl_enabled=false` → persist status `PARKED`, deduped ops alert, panel count; enable-flip reprocesses parked in stream order before new; quota escalation. Config module `configuration/support_ingress_configuration.py` (integration agent wires field + yaml).
3. **Classify/extract dispatcher** — new `operations/return_support/message_classification.py`, registered in `workers/integration_outbox.py` dispatch table (integration agent applies the registration line). Uses S2's `SupportAnalysisRecord` store: pin routing decisions before first invocation, CAS-accept per stage, reuse accepted results on retry, artifact writes only after `accepted_extraction`. LLM via `StructuredOutputInvoker` (anchor `ai/gateway/structured_invocation.py`; task wiring like `dynamic_knowledge/integration/model_gateway.py`), tasks `support.message.classify.v1` / `support.message.extract.v1` (integration agent adds ai_gateway.yaml blocks with shared tone/disclosure anchors; intent taxonomy injected from config, out-of-set → `other`). Output: intent fact, record groups → existing `record_support_outcome` path via the standard `support_response` signal chain (topic `return-case.support-response.signal`); loose artifacts → S1 binding module; omc mirror rows (`omc.return.update`, delivery identity) in the artifact-persistence transaction.
4. **Relay to A (DR-3)** — after artifacts/intent commit: (a) typed system entry appended to the Order Discovery conversation transcript — new entry kind on the conversation store (anchor: `AtomicConversationRepository` used by `dynamic_knowledge`; the entry is not a turn and must not disturb the turn-based agent contract); (b) panel sections via V1's section registry: return-records artifacts cards + support-thread digest. Multi-record fan-out: one entry per record with the configured do-not-mix framing (`support_ingress.multi_record_framing_prompt_key`). Outbound-to-B text (acks etc.): config-templated by default (`support_ingress.outbound_templates`), `support.outbound.compose.v1` only where configured; disclosure line always from config.
5. **Unmatched/ambiguous clarifications** — write the scoped facts (via S1 module) and compose the map-or-reject clarification (value, evidence span, candidate records) as fact `support_clarification_requested`; V3 owns the answer flow.
