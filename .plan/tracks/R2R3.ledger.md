## R2 — OpenAPI document honesty

### step:R2-01 — confirm the mechanism before changing nine fields

Measured on the published document before touching anything:
`CaseFactProjection` had **11 properties, 2 required** (`factId`, `factName`),
gap of nine: `acquisitionMethod`, `actorId`, `agentId`, `channel`, `observedAt`,
`recordedAt`, `sourceSystem`, `supersedesFactId`, `value`.

**Mechanism confirmed** by direct probe rather than assumed:

```
class M(BaseModel):
    a: str | None = None   ->  required: []      {"anyOf":[str,null], "default": null}
    b: str | None          ->  required: ["b"]   {"anyOf":[str,null]}
```

Any default — `= None` included — emits the field non-required. No default gives
required-and-nullable, which is exactly what the writer guarantees:

- `case_repository.append_scoped_case_fact:429-451` builds the document with
  every key present, `actorId` explicitly written with `None` included and an
  in-source comment saying why.
- `case_projection/assembly.py:487-501` (`project_facts`) binds all eleven
  fields explicitly on every construction — no spread, no conditional.

So *absent* and *null actor* stay distinguishable. Mechanism verified.

### step:R2-05 — the data assertion, and the gate that runs it (rule 13)

New `frontend/scripts/check-served-fields.js`. Reads the **generated**
`frontend/openapi/return-platform.openapi.json` as data and asserts
`CaseFactProjection`'s `required` array names all eleven properties.

**Wired into `contracts:check`**, which CI's `contract drift` job
(`.github/workflows/checks.yml`) runs:

```
contracts:served: node scripts/check-served-fields.js
contracts:check : contracts:generate && contracts:served && git diff --exit-code …
```

Ordered *before* the `git diff`, so a regression reports the missing field by
name instead of an opaque diff.

**Why a data assertion and not a type test — both traps confirmed empirically:**

- *The `Served<>` vacuous pass.* The alias is `{[K in keyof T]-?: …}`; it strips
  `?` regardless of the document, so any assertion against it or anything
  derived from it passes for nothing.
- *`tsc` invariance — measured, not argued.* See the injection below: with the
  defect reintroduced, `npx tsc -b` exits **0**. A typecheck injection here
  would be unpassable, so any red would be red for an unrelated reason.

The pin names all eleven fields in full rather than counting them: a count
passes when one field is renamed and another dropped. Three claims are reported
separately (pin still matches the schema / no new undeclared property / nothing
declared-but-not-required) so a rename and a lost `required` entry cannot read
as the same failure. The allowlist is deliberately per-schema, not global —
fourteen schemas legitimately under-declare today and a global rule would fail
on unauthorised work.
