# S2 — Delivery spine + review aggregate + context assembly

Self-contained brief. Read `.plan/contracts.md` — §§5–7, 10 are your contract; the S2/V1 boundary in §10 is frozen. Branch `feat/s2-delivery-spine` off the RV-approved commit recorded in `.plan/merge.md` after S1 merges. Ledger `.plan/tracks/S2.ledger.md`; commit per step `(S2) step:<id> …`.

## Scope

1. **`DurableCaseCommandStore`** — new `backend/src/return_platform/operations/case_commands.py`. Command record + outbox row in ONE Mongo transaction, modeled on `DurableSupportEventStore.record_support_response` (anchor: `operations/support_events.py`, unique `(caseId, supportEventId)`, `canonical_payload_digest`, outbox in-txn). Command doc: `{command_id, case_id, return_record_id?, kind, review_id?, draft_version?, canonical_edit_version?, signal_id, actor_id, payload, case_sequence}`; unique `(case_id, signal_id)`; CAS unique `(case_id, review_id, draft_version, canonical_edit_version)` → raise a conflict the API maps to 409. Outbox topic `return-case.command.signal` dispatched by the existing `TemporalSignalDispatcher` pattern (anchor: `operations/integrations/temporal_signal.py`), delivering signals `template_approved|template_revised|template_cancelled|reply_approved|reply_revised|reply_cancelled|clarification_answered` (payload carries `review_id` + `scope_id`; workflow-side handlers are V1's, not yours — you deliver, you don't handle).
2. **Review aggregate** — new `backend/src/return_platform/operations/review_aggregate.py` (+ repository/indexes). Full contracts.md §6: states `OPEN/APPROVING/SENT/DELIVERY_FAILED/HELD_FOR_OPERATIONS/CANCELLED/ABANDONED` with exactly the frozen transitions; `review_kind = TEMPLATE|SUPPORT_REPLY`; draft-edit store rows `(review_id, actor_id)` with `client_edit_id` idempotent upsert; canonical edit record; conflict marker (bump on conflict, clear on canonical-edit write); atomic `OPEN → APPROVING` (lock, reject conflicts/pending revisions, verify `draft_version` + `canonical_edit_version` + payload hash, persist frozen payload, create command + outbox in the same transaction); `ABANDONED` audited (actor/reason/timestamp); recovery command kinds `review_delivery_retry`/`review_abandon`; `actor=SYSTEM` reserved (reject as a client-supplied actor). All three stores (aggregate, command/outbox, draft-edit) in the same Mongo database/transaction scope.
3. **Delivery identity** — `logical_operation_id` (unique, derived from the approving command id) → `delivery_id` (minted once, stored, reused on retry) → `content_hash` (audit only); pre-send claim row unique on `delivery_id`. **Receiver dedupe:** add a unique partial index on `businessPayload.deliveryId` to `support_messages` and a thread-post path that honors it — anchor `operations/return_support/service.py` (`_ensure_indexes` ~428–451, `post_reminder` ~760 shows the dedupe-on-businessPayload pattern). New service methods `ensure_case_support_thread` (unique on `caseId`, loser re-reads — anchor `open_case_thread` ~667–753 already implements this shape; expose/reuse it) and `post_support_message` (kind-agnostic).
4. **Ordering** — extend the outbox claim path (`operations/integrations/outbox.py`, `workers/integration_outbox.py`): per-case streams `inbound|outbound|review_commands|omc`; unique `(case_id, stream, sequence)` allocated by CAS at enqueue; `event_id`/`causation_id`/`required_predecessor_ids[]` per contracts.md §7 (enqueue-validated, cycle-guarded, parentless dispatches immediately); claim skips rows whose predecessors are unfinished; dead-letter parks the stream + dependents, raises an ops alert, audited skip writes fact `support_stream_skip`.
5. **`SupportAnalysisRecord` store** — new module under `operations/return_support/` per contracts.md §5: one record per `support_event_id`, per-stage pinned routing decision (`release_id`, `routing_policy_version`, `ordered_candidate_routes[]` resolved BEFORE first invocation), attempts beneath the record, CAS-accepted result per stage, artifact-write gate on `accepted_extraction`, exhausted candidates → block + dead-letter. You build the store + gate; the LLM invocations are V2's.
6. **Context assembly** — new `backend/src/return_platform/platform/reasoning/case_context.py`: pure `assemble_case_context(facts, policy) -> AssembledContext` per contracts.md §10 (sort `(recordedAt, factId)`, scoped latest projection, pinned names, token budget with pinned tokenizer version, consumes persisted `context_summary`); separate write-once summary-generation step contract (invocation itself lands with V2/V3 consumers). New config module `configuration/context_assembly_configuration.py` (`ContextAssemblyConfiguration`, StrictConfigModel) — the integration agent wires the one-line field append + yaml block on your branch.
7. **Recovery adjustments** — `operations/return_case_recovery.py`: relaunch only confirmed-absent/unexpectedly-terminal executions (`AWAITING_TEMPLATE_REVIEW` is a legitimate wait); command committed but unapplied beyond the outbox retry horizon → operations surface, never auto-relaunch.

## Definition of done

Unit tests (normal suite): command+outbox atomicity (txn abort leaves neither); signal dedupe on `signal_id`; CAS 409 on stale `(draft_version, canonical_edit_version)`; every aggregate transition incl. both `ABANDONED` arrows and `HELD_FOR_OPERATIONS → OPEN`; autosave after `APPROVING` → 409; retry reuses delivery identity; receiver-dedupe index absorbs a duplicate post; thread ensure race (two creators → one thread); sequence CAS under concurrency; predecessor validation rejects unknown ids; parentless dispatch; dead-letter parks only its stream; analysis-record CAS (fallback attempt never mints a second record; all-candidates-unavailable dead-letters); `assemble_case_context` byte-identical for identical inputs (hash compare), compaction consumes-not-regenerates a persisted summary. `python -m pytest backend/tests` green. Ledger + delta report complete; nothing uncommitted.
