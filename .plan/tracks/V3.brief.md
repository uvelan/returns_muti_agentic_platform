## Scope

1. **Placement verdict (first step, ledger-recorded).** Inspect `operations/return_support/auto_responder.py` + `agents/support_response.py`. Extend them if they can carry the resolution ladder; build a new graph module only on a written verdict that they cannot. If a new graph: LangGraph with `SystemStoreCheckpointSaver` (anchor `platform/reasoning/checkpoint.py`; InMemorySaver forbidden by test), thread id `support-resolver:{case_id}:{support_event_id}` (attempt = metadata, never in the key), state TypedDict with a checkpoint allowlist + redaction test (anchor `tests/dynamic_knowledge/test_order_agent_graph_state.py` pattern).
2. **Resolution ladder** for `info_request`-class intents: case facts (via S2's `assemble_case_context` + `latest_case_facts_scoped`) → graph with the agent's own on-demand sync (anchor `dynamic_knowledge/on_demand_sync/coordinator.py`) → registered tools → associate clarification. Thresholds `support_resolver.fact_confidence_millionths` / `graph_confidence_millionths`; sub-threshold, conflicting sources, or missing required entity → escalate, never answer. `per_case_llm_budget` exhaustion → fact `support_resolver_budget_exhausted` + escalation. Task `support.question.resolve.v1` via `StructuredOutputInvoker`; summary generation via `support.context.summarize.v1` write-once step (S2's contract). Prompt records `consumed_fact_ids`.
3. **Tool router** — new `platform/capabilities/tool_router.py` per contracts.md §9 boundary: classification → validated intent + required-entity schema; config `support_resolver.tool_bindings[]` maps intent → `(capability, contract)` in the existing `CapabilityRegistry` (anchor `platform/capabilities/contracts.py`); arguments only from case facts/graph, validated against `input_schema_ref`; refuse on missing entities; credentials via `CredentialBindingConfiguration` platform-side — never in agent state (extend the redaction allowlist test). Raw support text never names a tool or supplies an argument — enforce structurally, assert in tests.
4. **Reply gating** — `reply_gate{default: review_required, per_intent{}}`: gated answers become `SUPPORT_REPLY` reviews on S2's aggregate (server-minted `scope_id`), approved via V1's `/reviews/{id}/approve` endpoints and delivered via `post_support_message`; `auto_reply` intents send directly through the same delivery path with `actor=SYSTEM` provenance + disclosure line.
5. **Clarification round-trip** — new `api/case_clarifications.py` (`POST /api/v1/cases/{case_id}/clarifications/{clarification_id}/answer`, `RETURNS_SUPPORT_ACT` + case access) → `DurableCaseCommandStore` (command + outbox) → signal `clarification_answered` → activity `record_clarification_answer` (fact, method=STATED, channel=CHANNEL_A, actorId) + `relay_clarification_to_support` (outbox `return-case.support-outbound`, delivery identity, templated text + disclosure) + deadline reset per `clarification_resets_deadline`. Implements the handler stub V1 declared in the workflow. Reminders continue across the wait (assert no duplicates).
6. **Frontend** — clarifications panel section via V1's registry: verbatim support question, why-unresolvable, what-was-tried, needed field, inline answer form (routes to the answer endpoint), map-or-reject UI for unmatched artifacts; reply-review entries render through V1's review components (`review_kind` aware). MSW handlers.

## Definition of done
Tests in-slice: ladder short-circuits (facts-answerable → no graph/tool call); sub-threshold → escalation, no answer; tool refusal on missing entity; injection fixture → no tool selection from raw text; credential absent from checkpointed state (redaction test); budget exhaustion; gated reply lands as `SUPPORT_REPLY` review and is visible/approvable; auto_reply carries disclosure; answer endpoint → fact + signal + relay row + deadline reset; resolver retry resumes at last completed node (checkpointer test); Vitest a11y for the clarification form. Suites green; ledger + delta report + handoff spec committed.
