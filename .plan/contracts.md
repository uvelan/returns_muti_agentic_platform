## 6. Review aggregate (S2 substrate, V1/V3 surface)

- **Unit:** support request. `support_gate.request_grouping` declarative rule enum `one_per_case | by_shipping_mode | by_ship_from` (default `one_per_case`). One review + one outbound payload per request; per-record sections retain `return_record_id` + own snapshot mapping. One case-level support thread; artifacts bind to records.
- **`review_id`:** opaque per-attempt id scoped `(case_id, request_id)`; `redraft` mints a new attempt under the same scope. `review_kind = TEMPLATE | SUPPORT_REPLY`, both on the aggregate with full guarantees; gap/variant rules TEMPLATE-only. Reply-review `scope_id` minted server-side by the gating transition.
- **State machine:** `OPEN → APPROVING → SENT`; `APPROVING → DELIVERY_FAILED | HELD_FOR_OPERATIONS`; `OPEN → CANCELLED`; `DELIVERY_FAILED → APPROVING` (authorized retry, same delivery identity) `| ABANDONED`; `HELD_FOR_OPERATIONS → OPEN` (blocking condition cleared) `| ABANDONED`. `ABANDONED` is terminal, audited (actor, reason, timestamp), panel-visible. `actor=SYSTEM` is reserved and non-assignable.
- **Edit model:** `draft_version` / `edit_version` / `base_draft_version` / `client_edit_id`; mutable draft-edit store one row per `(review_id, actor_id)`, coalesced autosaves (not facts); canonical edit `{canonical_edit_version, canonical_payload, resolved_from_actor_edit_ids[], resolved_by, resolved_at}` — sole-actor submits auto-promote; conflicts must be resolved (select/merge/discard) to a canonical edit before approval. Conflict-presence marker (case-scoped, versioned) bumped on conflict appearance, **cleared by the canonical-edit write**; participates in the shared panel hash; private edit contents never do.
- **Approval (`OPEN → APPROVING`, atomic):** locks the review; rejects unresolved conflicts and pending revisions; verifies expected `draft_version` + expected `canonical_edit_version` + canonical approved-payload hash (**that exact field name** in request bodies and command payloads); persists the frozen approved payload; creates command + outbox row. Frozen CAS key: unique `(case_id, review_id, draft_version, canonical_edit_version)` → 409. From `APPROVING` on, edit/cancel/redraft return 409 (UI surfaces the transition, not a bare error). Version authority = fact + edit stores, never a Temporal query. `auto_send` = same transition with `actor=SYSTEM`, refused by the same rejections; **an unresolved required gap forces hold/escalate regardless of `on_timeout: auto_send`**.
- **Guard-blocked at deadline** → `HELD_FOR_OPERATIONS`, reason `TEMPLATE_REVIEW_GUARD_BLOCKED`.
- **Recovery surface:** `POST .../reviews/{review_id}/recovery/{retry|abandon}` → command kinds `review_delivery_retry` / `review_abandon`, capability `RETURNS_REVIEW_RECOVERY` + case access. Retry reuses `logical_operation_id`, `delivery_id`, frozen payload; a retry absorbed by receiver dedupe still reaches `SENT`.
- **Transactional boundary:** review aggregate + command/outbox + draft-edit store **co-located in one transactional datastore** (Mongo). If ever split: outbox and edit reads driven from the review aggregate; no cross-store transaction claimed.
- **Statuses & park reasons:** case status `AWAITING_TEMPLATE_REVIEW` (a legitimate wait — recovery never relaunches it); park reasons `TEMPLATE_REVIEW_UNANSWERED`, `TEMPLATE_REVIEW_CANCELLED`, `TEMPLATE_REVIEW_GUARD_BLOCKED`.
- **Workflow gate:** inserted in `_open_support` between `draft_support_request` and the send path, under `workflow.patched("support-template-review-gate")`; all request drafts created first, then **one map-based wait loop** over `{request_id → review state}` cloned from the `_await_policy_override` pattern (registered duplication — see §10); per-case reminder cadence (DR-7), deadline via `resolve_business_deadline`, resume field `resumed_template_review_deadline_iso` in `_continued_input()`. Config `support_gate.template_review{enabled: true, review_wait_seconds, reminder_interval_seconds, max_reminders, on_timeout: auto_send|hold|escalate = hold}`.
